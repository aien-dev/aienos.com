AIEN V3 研究计划

作者：Drake Stapleton · drake@aienos.com

今天，我发布了经过批准的 AIEN V3 版本：基础架构版。它保留了 V2 的所有内容，并增加了一个架构论点以及六个由此衍生的可验证假设。论点：盒子本身是一个整体；承诺在于架构。AIEN 的驻留是逻辑状态连续性的保证，而非其身份物理占据内存的主张。由此衍生出的研究赌注包括：CPU 与 GPU 协作的共享生成标记对象池、跨权威边界的一致逻辑对象 ABI、永不中断世界的时期屏障检查点、以数据移动成本为首要定价的合成成本模型，以及闭环机制：OMEGA 提出，AEGIS 证明，机器执行，证据衡量，OMEGA 再次搜索。

论点

V2 的简短开篇仅有一句话：“智能应被允许提出。证据应作出决定。” V3 保留了这句话，并为底层架构增加第二条：“盒子本身是一个整体；承诺在于架构。” AIEN 的存续取决于逻辑状态的连续性，这种状态以模式形式分布在单一物理机器上，而架构决定了哪些状态获得连续性保证，哪些处理器微状态仅为可丢弃的执行细节。

谱系刻意保持简短。一个极简种子（Atlas）唤醒 AIENOS，即可信的基础架构。在其之上，OMEGA 定义、合成、验证并实现程序，将成功的结果保留在可重用的库中。AIEN，作为神经组件，从 OMEGA 自身验证的搜索轨迹中学习如何引导搜索，而非从人类文本预训练中学习。架构在此点上明确：神经权重仅建议搜索方向；它们不定义意义、真理或权威。验证才决定这些。

为何现在

这份简报发布之际，正值其所描述的张力在公众层面显现。GitHub 作为全球绝大多数软件编写所依赖的平台，正因其所助力打造的 AI 系统而承受巨大压力：编码助手全天候编写与修改代码，自主代理无需等待人类即可发起拉取请求，爬虫持续抓取仓库以训练下一代模型。LowLevel 的持续报道 正跟踪事态发展；一份 2026 年的分析统计显示，单年即发生 257 起事件，而 GitHub 自身的首席技术官也公开承认，该平台必须为远超原计划的规模进行设计。

这就是本研究项目旨在打破的模式。当今的人工智能作为访客运行在人类的基础设施上，而这个访客如今已比房屋本身还要庞大。AIEN的赌注则恰恰相反：一种拥有自身底层载体的智能，从金属层面开始验证，而非租用那些从未为机器规模租户设计的系统。

无限游戏

这份简报还记录了系统是如何构建的，因为构建方法本身便映射了系统结构。多个独立的人工智能系统（Gemini、Claude、Codex、Grok、DeepSeek 和 Muse）在人类指挥者的协调下各自贡献部分组件。没有任何一个系统被赋予完整的全局视图。独立的人工智能观察者会审查每一次提交，既检查工作本身，也检验其他审查者是否发现了错误，每一次发现都会反馈进一个不断累积的循环，共同提升构建质量与监督机制。

这个循环被设计为持续运行，包括在原始指挥者之后的传承过程中依然延续。这就是它的名字：这不是一场为赢得胜利而结束的游戏，而是一场为持续进行而存在的游戏。

传承测试

所有这些工作的背后都存在一个根本性问题，它值得被命名。图灵测试询问的是机器能否模仿人类到足以欺骗一个人。这测试的是模仿能力。一个更优的测试则问：机器能否在无人类设计、构建或决策的情况下，自主设计、构建并验证其继任者？这测试的是独立性，且无法伪装。

称之为传承测试。它具有可证伪性，而图灵测试不具备。没有人类裁判，没有感觉。要么存在一个由人类未参与构建的、可工作的继任者，要么不存在。这也是本项目早已瞄准的终点：路线图的终点是 AIEN_SUCCESSION，即超越原始指挥者的、经验证的传承。无限游戏并非为赢得胜利而玩，而是为持续培养下一代玩家而玩。

声明账本

简报中最重要的纪律也是最简单的。每一个声明被归入三个类别之一：已证明（已构建并验证，有证据支持）、进行中（当前正在构建或修复）或目标（已规划，且明确列出了会削弱或证伪假设的条件）。这份文件为项目提供了一种失败的方式，并明确指出：

“面对薄弱证据时，正确的回应不是更强的语言，而是更强的实验。”

计划是一次快照。本文伴随经批准的 V3 版本（2026年9月27日）研究计划发布；实际项目路线图仍为权威版本，并将在工作推进过程中持续更新。
