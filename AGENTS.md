# AienOS website (aienos.com)

> Static site for aienos.com. One Rust program, `crates/site-builder`, renders every page from Maud templates, copies hand-written files from `public/`, then rewrites every head and writes the machine surface. GitHub Pages serves the output; `.github/workflows/pages.yml` builds and deploys it on every push to `main`.

Shared rules: read https://www.aienos.com/agents/RULES.md first. This file adds what is specific to this repository; where the two differ, this file wins here. The rules live in `public/agents/RULES.md`; every public repository is listed at https://www.aienos.com/agents/ (`components/agents.rs`, data refreshed by `site-builder agents`). The catalog follows every GitHub API page, includes archived repositories as read-only references, and links the actual `AGENTS.md` or `CLAUDE.md` when present. Missing instructions are marked explicitly. AienOS is the whole system at its current `aien-dev/aienix` URL until renamed; Aienux is the separate kernel.

## Scope

- Applies to the whole repository.
- Source of truth is `crates/site-builder/src` plus `public/`. The root `index.html` and `dist/` are not the live site.
- `dist/` is generated output. Never edit it by hand; rebuild it.
- `crates/hive-feed` is opt-in Rust website telemetry tooling. It does not run during static builds. `scripts/hive/` holds its service and exact-route edge templates; README documents installation and the publication boundary.

## Installation

```bash
git clone https://github.com/aien-dev/aienos.com.git
cd aienos.com
rustup toolchain install stable
cargo build --release --manifest-path crates/site-builder/Cargo.toml
```

There is no Node build, no `package.json`, and no package manager. The only tool needed is a Rust toolchain; the site depends on `maud`, `serde` and `serde_json`.

## Configuration

- `facts.json` at the repository root is read by every build. Refresh it from the public GitHub record when the fact sheet must move:

```bash
GH_TOKEN="$(gh auth token)" cargo run --release --manifest-path crates/site-builder/Cargo.toml -- facts facts.json
```

- `public/data/project-progress.json` feeds `/progress/`. Recollect it with:

```bash
GH_TOKEN="$(gh auth token)" cargo run --release --manifest-path crates/site-builder/Cargo.toml -- progress public/data/project-progress.json
```

- `CNAME` holds the custom domain. `.github/workflows/pages.yml` is the deployment configuration.
- `crates/site-builder/data/research_status.json` is the canonical research ladder and experiment verdicts.
- `/dash/` reads `public/data/accounts.tsv` and `routing.tsv`, which the pages workflow lays in from the `data/now` branch. The Spark writes them with `~/.local/bin/dash-snapshot` (called by `now-publish`). Accounts are numbered per provider; never publish an email, account id, org or project name. `components::dash::word` strips `@` and markup as a second guard.
- The page registry in `crates/site-builder/src/seo.rs` (`seo::PAGES`) drives the sitemap, `llms.txt`, `sitemap.md`, the feeds and the JSON-LD. Add every new page there or the build fails.

## Usage

```bash
# Full test suite
cargo test --workspace

# Build the site into dist/ (this also runs the integrity verifier)
cargo run --release --manifest-path crates/site-builder/Cargo.toml -- build dist

# Re-check an existing dist/ without rebuilding
cargo run --release --manifest-path crates/site-builder/Cargo.toml -- verify dist

# Preview the generated output locally
python3 -m http.server 8080 --directory dist
```

Open `http://127.0.0.1:8080/` after the preview server starts. GitHub Pages serves directories through `index.html`, so local previews match the live routes.

## Conventions

- Generated pages are Maud markup in `crates/site-builder/src/components/`. Hand-written pages live under `public/<route>/index.html` and are copied verbatim. `/hive/` is the one exception: its skeleton is generated by `om/hive-page/hive.om` and only embedded by `components/hive.rs`.
- Every page gets its head rewritten by `seo::enrich`: canonical on `https://www.aienos.com`, Open Graph and Twitter cards, hreflang, JSON-LD, `rel="alternate" type="text/markdown"`, `rel="describedby"` to `/llms.txt`, and robots snippet directives. Do not duplicate those tags in a component.
- Every page also gets a Markdown mirror at the same path with `.md` (`/` becomes `/index.md`), with YAML frontmatter and a `## Sitemap` section. The mirror is generated from the final HTML; do not hand-write one.
- Copy rules: no em dashes, no en dashes, no outside fonts, scripts or trackers. The verifier fails the build on a dash in a page.
- Keep one source for machine-readable state. `status.json`, the status section, and the current-state lines in `llms.txt` all read `components::status::layer_states()`.
- Tests live beside the code in `#[cfg(test)]` modules. Add a test when a rule can regress silently.
- Hive's page structure and browser hydrator are generated by seeded Omega, never written in Rust or hand-edited in `public/js/`. `om/hive-page/check.sh` concatenates `contract.om`, `hive.om` and `hive-js.om` into one program: stdout emits the skeleton, fd 3 emits `hive.js`. The shared contract table owns the served ids, template ids, data-f slot names, poll interval and freshness bounds; `~N~` tokens in both units interpolate that table. Append contract entries rather than renumbering them. `hive.om` owns the section set and order (`meta`, eight pipe separated fields per record), aria wiring, bounded panel heads/bodies, mission tree, rows, templates and empty states. `fld` emits one interpolated field and `secthead` emits fields one to seven; `main` calls the section body, then emits field eight. Newlines and `|` are forbidden inside a meta field. The site-wide `turing-look.js` has its own independent generator, `turing-look.om`, in the same gate. The gate verifies `omc.sha256`, runs each program twice, requires byte-identical nonempty outputs, and writes `main.html` plus both served scripts and their `.sha256` sidecars. Commit sources, artifacts and hashes together. Run the gate twice (both exit 0), site-builder tests and `scripts/test-hive-cosmic.py`; the tests reject any artifact/hash disagreement without executing the arm64 compiler on x86_64. `components/hive.rs` only embeds the markup, while the generated hydrator only clones templates and fills text nodes. A structure change belongs in `hive.om`; a browser-behaviour change belongs in the corresponding function text in `hive-js.om`, never in generated `public/js/hive.js`. Both `public/js/hive.js` and `public/js/turing-look.js` are generated, never hand-edited.
- `.github/workflows/generated-hive.yml` runs only the skeleton-hash and generated-script-hash tests on x86_64 for relevant pull requests and main pushes. It does not run `omc`, regenerate artifacts or change the full-suite-on-Spark policy.
- Hive freshness has a seeded WebAssembly backend: `om/hive-page/fresh.om` takes the current/effective source clock, generated timestamp, previous timestamp, stale threshold and fetch status; the threshold remains a caller input, not a duplicated policy constant. `freshness-js.om` emits the loader and explicit JavaScript fallback (`window.hiveFresh`); `data-fresh-engine="wasm|js"` and `data-fresh-state="0|1|2|3"` expose which decision ran. States are fresh, source stale (strictly past the threshold), timestamp moved backwards, and fetch aborted; backwards retains priority over abort. Clock-trust gating remains outside this scalar decision. `check.sh` compiles it through `omc ir` and the vendored, hash-pinned `irwasm` to `public/wasm/hive-fresh.wasm`; provenance lives in `irwasm.provenance`. The site omc pin stays unchanged. The existing generated-script hash test also checks the wasm on x86_64 without executing either arm64 tool. `sh om/hive-page/gate-fresh.sh` uses real AArch64 drivers and Node solely as a read-only wasm oracle, never a build dependency.
- Hive keeps its Omega-generated information board. At Drake's explicit request for a universe presentation, the scene behind the masthead is Allen's two black holes, and the decorative galaxy (public/assets/hive-universe.svg) is only the residual sky behind them, dimmed and reasserted in the presentation block at the end of public/assets/hive.css. The scene must not represent agent positions, progress, topology or live activity, and no invented coordinates or data are allowed. It is a decoration over the board, never a source: the board itself is a status and freshness strip, a mission tree indented by depth, compact agent rows (name, status, model and provider, elapsed, current activity), a selected-agent manifest and a message feed. The missions panel and the manifest panel are bounded: their head never scrolls, only their body does, so a fleet of hundreds of agents is one scroll box rather than a document thousands of pixels tall, and the search tools stay at the top of the missions scroll body. The manifest panel is sticky beside the missions panel, and it stacks under it below 900px. Branches collapse: the row template declares a disclosure button carrying `aria-expanded` and `aria-controls`, `public/js/hive.js` assigns the id it points at, hides it on a leaf row and keeps one expanded state per branch. A branch holding more than twelve agents starts folded and says how many it holds, because the reported fleet is wide rather than deep; a search opens the branches that contain a match without discarding the state the reader chose, and choosing an agent opens the path down to it. Sections carry `data-requires` in the emitted markup, so a section the snapshot has no data for is hidden rather than shown empty; which sections exist and in what order is decided in `hive.om`. Task, activity and lifecycle data must come from real observations. Preserve source freshness, partial coverage, unknown states, message-time model identity, keyboard focus, and reduced-motion support.
- The page says what it is. The masthead eyebrow and the `hive-omega` band state that the page is written in Omega, that every heading, panel, row and template comes from `om/hive-page/hive.om`, and that glitches are expected while the language is still being finished. That claim lives in `hive.om` and stays visible above the fleet; `scripts/test-hive-cosmic.py` fails if it disappears.
- The scene is Allen's law, and the `.om` owns every number of it. `native/kernel/ui/night.c` (`orbit_angle`, `ck_night_at`) and `chirp.c` in the `aienos-allen-portable-build` tree are the source: separation as t^(1/4), angle as t^(5/8), t the time left, with the wide orbit at 270 units and one turn per 5200 ms, the shadows grown in from 2600 and 4000 ms, the merger at 12000 ms with a shadow from 323/256 to 2 of a single one and a glow of 362/256, the last hole gone at 15200 ms and the ripple out to 15600 ms. That law is real (section 4 of `docs/ALLEN_SKY_SCIENCE.md`); the ripple across the sky and the ringing of the last hole are illustration, not evidence, and the page says so. `om/hive-page/hive.om` samples it with integer and `f64` arithmetic and emits the markup, the keyframes and the wiring into `main.html`; `public/assets/hive.css` only places the stage and paints the discs, and animates nothing. Never hand write a sample, a keyframe or a duration in the stylesheet: a change to the sequence is an edit to the `.om` and then `sh om/hive-page/check.sh`.
- The scene is a stable layer. The residual sky is a composited background with `transform: translateZ(0)`, `will-change: transform` and `contain: paint`, kept at `background-size: cover` because the band is wide and short: any height-relative size leaves a bare strip of page background on the right, and at 1365x768 cover downscales (0.785x) rather than upscaling. Never put a scene layer on a negative z-index under `isolation: isolate`: that made Chromium rebuild the layer during scroll and the background flickered badly (reported 2026-10-25); the layer promotion is the whole fix. Content sits at z-index 2, the scrim at 1, the holes at 0, and `scripts/test-hive-cosmic.py` enforces each of those rules.
- The whole sequence is compositor only. Every animated property in the artifact is `transform` or `opacity`, the holes and the merged shadow are absolutely positioned in the masthead's own layer so the scene cannot cause layout, and each sample is a `translate3d` or a `scale` of one element. The animations are attached only inside the artifact's `@media (prefers-reduced-motion:no-preference)` block and only while the page's own control has set `data-motion="on"`, so a reader with reduced motion, and a reader who paused motion, both get one static frame of the sequence (the pair at a visible separation at 7000 ms, no merged hole, no ripple) and `document.getAnimations()` is empty. `scripts/test-hive-cosmic.py` pins the property set, the motion gate and the frame.
- Hive surfaces use the shared palette tokens (`--bg-base`, `--bg-surface`, `--bg-card`, `--bg-card-hover`, `--border-subtle`, `--text-primary`, `--text-secondary`, `--text-muted`), never a bespoke near-black or a local hex palette. Its motion stays compositor-only: animate transform and opacity, never `filter` or `box-shadow`, and cap change highlights so a busy fleet cannot strobe. Text lines that the feed rewrites every second are clamped to a fixed line count so the page cannot reflow under the pointer; the row activity line reserves its two lines with `min-height`, so a shorter or longer observation never resizes a row the pointer is over. There is one transition in `hive.css` (the disclosure chevron's `transform`), and it is removed both under `prefers-reduced-motion` and whenever the page's own motion control sets `data-motion="off"`. The scene never touches the text: prose sits on a scrim of `--bg-base` mixed to a partial alpha (`color-mix`, never a new near-black), at least 0.88 opaque over every line at 1280 and at 390 CSS px, which keeps `--text-primary` above 13:1 and `--text-secondary` and `--text-muted` above 5:1 even against the brightest pixel the scene can produce. The holes are placed to the right of the prose on a wide band and above it on a phone, and the masthead clips them, so they never cross the information board.
- Hive text passes a field whitelist and full-string privacy screening before truncation. Never serialize raw sessions, system/task prompts, tool payloads, hidden reasoning, credentials, or control metadata. Direct Drake messages, short task-summary fields and public agent replies require the authorized publication boundary. Render feed strings through text nodes, not HTML.

## Safety and approvals

- Ask before changing the canonical host, the page registry shape, or a published claim that carries a receipt.
- Never commit tokens, API keys, or `.env` files. `GH_TOKEN` is read from the environment and is never written into the site.
- Never publish `dist/`, `.crumb.local`, or private evidence. `.gitignore` and the copy step already exclude local coordination files.
- Do not run destructive git commands or rewrite published history. Work on a branch, run the full test suite and `build dist`, then merge through a pull request.
