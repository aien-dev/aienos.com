# AienOS website (aienos.com)

> Static site for aienos.com. One Rust program, `crates/site-builder`, renders every page from Maud templates, copies hand-written files from `public/`, then rewrites every head and writes the machine surface. GitHub Pages serves the output; `.github/workflows/pages.yml` builds and deploys it on every push to `main`.

Shared rules: read https://www.aienos.com/agents/RULES.md first. This file adds what is specific to this repository; where the two differ, this file wins here. The rules live in `public/agents/RULES.md`; every public repository is listed at https://www.aienos.com/agents/ (`components/agents.rs`, data refreshed by `site-builder agents`). The catalog follows every GitHub API page, includes archived repositories as read-only references, and links the actual `AGENTS.md` or `CLAUDE.md` when present. Missing instructions are marked explicitly. AienOS is the whole system at its current `aien-dev/aienix` URL until renamed; Aienux is the separate kernel.

## Scope

- Applies to the whole repository.
- Source of truth is `crates/site-builder/src` plus `public/`. The root `index.html` and `dist/` are not the live site.
- `dist/` is generated output. Never edit it by hand; rebuild it.
- `crates/hive-feed` is opt-in Rust website telemetry tooling. It does not run during static builds. `scripts/hive/` holds its service and exact-route edge templates; README documents installation and the publication boundary.

## Installation

```bash
git clone https://github.com/aien-dev/aienos.com.git
cd aienos.com
rustup toolchain install stable
cargo build --release --manifest-path crates/site-builder/Cargo.toml
```

There is no Node build, no `package.json`, and no package manager. The only tool needed is a Rust toolchain; the site depends on `maud`, `serde` and `serde_json`.

## Configuration

- `facts.json` at the repository root is read by every build. Refresh it from the public GitHub record when the fact sheet must move:

```bash
GH_TOKEN="$(gh auth token)" cargo run --release --manifest-path crates/site-builder/Cargo.toml -- facts facts.json
```

- `public/data/project-progress.json` feeds `/progress/`. Recollect it with:

```bash
GH_TOKEN="$(gh auth token)" cargo run --release --manifest-path crates/site-builder/Cargo.toml -- progress public/data/project-progress.json
```

- `CNAME` holds the custom domain. `.github/workflows/pages.yml` is the deployment configuration.
- `crates/site-builder/data/research_status.json` is the canonical research ladder and experiment verdicts.
- The page registry in `crates/site-builder/src/seo.rs` (`seo::PAGES`) drives the sitemap, `llms.txt`, `sitemap.md`, the feeds and the JSON-LD. Add every new page there or the build fails.

## Usage

```bash
# Full test suite
cargo test --workspace

# Build the site into dist/ (this also runs the integrity verifier)
cargo run --release --manifest-path crates/site-builder/Cargo.toml -- build dist

# Re-check an existing dist/ without rebuilding
cargo run --release --manifest-path crates/site-builder/Cargo.toml -- verify dist

# Preview the generated output locally
python3 -m http.server 8080 --directory dist
```

Open `http://127.0.0.1:8080/` after the preview server starts. GitHub Pages serves directories through `index.html`, so local previews match the live routes.

## Conventions

- Generated pages are Maud markup in `crates/site-builder/src/components/`. Hand-written pages live under `public/<route>/index.html` and are copied verbatim. `/hive/` is the one exception: its skeleton is generated by `om/hive-page/hive.om` and only embedded by `components/hive.rs`.
- Every page gets its head rewritten by `seo::enrich`: canonical on `https://www.aienos.com`, Open Graph and Twitter cards, hreflang, JSON-LD, `rel="alternate" type="text/markdown"`, `rel="describedby"` to `/llms.txt`, and robots snippet directives. Do not duplicate those tags in a component.
- Every page also gets a Markdown mirror at the same path with `.md` (`/` becomes `/index.md`), with YAML frontmatter and a `## Sitemap` section. The mirror is generated from the final HTML; do not hand-write one.
- Copy rules: no em dashes, no en dashes, no outside fonts, scripts or trackers. The verifier fails the build on a dash in a page.
- Keep one source for machine-readable state. `status.json`, the status section, and the current-state lines in `llms.txt` all read `components::status::layer_states()`.
- Tests live beside the code in `#[cfg(test)]` modules. Add a test when a rule can regress silently.
- Hive's page structure is generated, not written in Rust. `om/hive-page/hive.om` is a seeded Omega program in program mode that writes the whole `/hive/` skeleton to stdout: the section set and order (the `meta` table, one record per section and eight pipe separated fields per record), the ids and aria attributes, the bounded panel heads and scroll bodies, the mission tree container, the compact agent row with its branch disclosure, the message and field templates, the strip, the empty states and the jump navigation. A record is terminated by a newline and its fields by `|`, so no field may contain either: multi-line markup lives in the `text` constants and is written by the section body functions. `fld` emits one field and `secthead` emits fields one to seven, `main` calls the body function, then emits field eight, the section close. `sh om/hive-page/check.sh` compiles it with the pinned compiler (`om/hive-page/omc.sha256`), runs it twice, and keeps `om/hive-page/main.html` with `main.html.sha256`. Commit the artifact and the digest with the `.om` change; `components/hive.rs` only embeds the bytes, and the site test fails when the two disagree. GitHub Pages CI is x86_64 and cannot execute the AArch64 pin, so CI verifies bytes only. A structure change is an edit to `hive.om` plus `check.sh`, never markup in a component or DOM construction in `public/js/hive.js`, which only clones the emitted templates and fills text.
- Hive keeps its Omega-generated information board. At Drake's explicit request for a universe presentation, a local decorative galaxy may appear behind the masthead (public/assets/hive-universe.svg, reasserted in the presentation block at the end of public/assets/hive.css and checked by scripts/test-hive-cosmic.py); it must not represent agent positions, progress, topology or live activity, and no invented coordinates or data are allowed. It is a decoration over the board, never a source: the board itself is a status and freshness strip, a mission tree indented by depth, compact agent rows (name, status, model and provider, elapsed, current activity), a selected-agent manifest and a message feed. The missions panel and the manifest panel are bounded: their head never scrolls, only their body does, so a fleet of hundreds of agents is one scroll box rather than a document thousands of pixels tall, and the search tools stay at the top of the missions scroll body. The manifest panel is sticky beside the missions panel, and it stacks under it below 900px. Branches collapse: the row template declares a disclosure button carrying `aria-expanded` and `aria-controls`, `public/js/hive.js` assigns the id it points at, hides it on a leaf row and keeps one expanded state per branch. A branch holding more than twelve agents starts folded and says how many it holds, because the reported fleet is wide rather than deep; a search opens the branches that contain a match without discarding the state the reader chose, and choosing an agent opens the path down to it. Sections carry `data-requires` in the emitted markup, so a section the snapshot has no data for is hidden rather than shown empty; which sections exist and in what order is decided in `hive.om`. Task, activity and lifecycle data must come from real observations. Preserve source freshness, partial coverage, unknown states, message-time model identity, keyboard focus, and reduced-motion support.
- The page says what it is. The masthead eyebrow and the `hive-omega` band state that the page is written in Omega, that every heading, panel, row and template comes from `om/hive-page/hive.om`, and that glitches are expected while the language is still being finished. That claim lives in `hive.om` and stays visible above the fleet; `scripts/test-hive-cosmic.py` fails if it disappears.
- The scene is a stable layer. The galaxy is a composited background with `transform: translateZ(0)`, `will-change: transform` and `contain: paint`, kept at `background-size: cover` because the band is wide and short: any height-relative size leaves a bare strip of page background on the right, and at 1365x768 cover downscales (0.785x) rather than upscaling. Never put it on a negative z-index under `isolation: isolate`: that made Chromium rebuild the layer during scroll and the background flickered badly (reported 2026-10-25); the layer promotion is the whole fix. Content sits at z-index 2, the scrim at 1, the scene at 0, and `scripts/test-hive-cosmic.py` enforces each of those rules.
- Hive surfaces use the shared palette tokens (`--bg-base`, `--bg-surface`, `--bg-card`, `--bg-card-hover`, `--border-subtle`, `--text-primary`, `--text-secondary`, `--text-muted`), never a bespoke near-black or a local hex palette. Its motion stays compositor-only: animate transform and opacity, never `filter` or `box-shadow`, and cap change highlights so a busy fleet cannot strobe. Text lines that the feed rewrites every second are clamped to a fixed line count so the page cannot reflow under the pointer; the row activity line reserves its two lines with `min-height`, so a shorter or longer observation never resizes a row the pointer is over. There is one transition in `hive.css` (the disclosure chevron's `transform`), and it is removed both under `prefers-reduced-motion` and whenever the page's own motion control sets `data-motion="off"`. The galaxy never touches the text: prose sits on a scrim of `--bg-base` mixed to a partial alpha (`color-mix`, never a new near-black), at least 0.88 opaque over every line at 1280 and at 390 CSS px, which keeps `--text-primary` above 13:1 and `--text-secondary` and `--text-muted` above 5:1 even against the brightest pixel the scene can produce.
- Hive text passes a field whitelist and full-string privacy screening before truncation. Never serialize raw sessions, system/task prompts, tool payloads, hidden reasoning, credentials, or control metadata. Direct Drake messages, short task-summary fields and public agent replies require the authorized publication boundary. Render feed strings through text nodes, not HTML.

## Safety and approvals

- Ask before changing the canonical host, the page registry shape, or a published claim that carries a receipt.
- Never commit tokens, API keys, or `.env` files. `GH_TOKEN` is read from the environment and is never written into the site.
- Never publish `dist/`, `.crumb.local`, or private evidence. `.gitignore` and the copy step already exclude local coordination files.
- Do not run destructive git commands or rewrite published history. Work on a branch, run the full test suite and `build dist`, then merge through a pull request.
